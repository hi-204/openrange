# OpenRange — Plan

Status: **planning (pre-M0)** · Last updated: 2026-10-24

OpenRange is a local, offline, open-source No-Limit Hold'em study suite: a validated
CFR solver (Rust → WebAssembly + native CLI), a trainer graded by EV loss, and a
course from "what is a blind" to solver literacy. This file is the roadmap. How the
pieces fit is in [ARCHITECTURE.md](ARCHITECTURE.md); why each choice was made is in
[DECISIONS.md](DECISIONS.md); what is actually done is in [STATE.md](STATE.md).

## Guiding rules (short form — full text in CLAUDE.md)

1. No strategy number reaches the UI unless a script in this repo produced it.
   Everything carries provenance (`solver_exact` | `solver_approx` | `authored`).
2. The solver passes the validation suite before any trainer feature uses it.
3. Approximations are labeled in the UI and listed in KNOWN_LIMITS.md.
4. Study tool only: no live assistance of any kind.
5. Offline and private: zero runtime network requests; user data is local and exportable.
6. A user needs only Node.js to run the app. Rust is needed only to rebuild the solver.

## Milestones and exit criteria

Every milestone ends with: all tests green, app runs, commit(s), STATE.md updated, and a
short plain-English report (what works, how to try it in PowerShell, what's approximate,
what's next).

### M0 — Scaffolding
- Repo layout from the spec, Cargo workspace (`solver-core`, `solver-cli`, `solver-wasm`),
  npm workspace (`web`), `.gitattributes` / `.gitignore` / `.editorconfig`, pinned toolchains.
- `solver-wasm` exports `version()` and a trivial computation; prebuilt `.wasm` committed to
  `web/public/wasm/`; the web app calls it **from a Web Worker** and displays the result.
- `npm run build:wasm` (Node script, no bash) rebuilds the WASM.
- CI workflow (GitHub Actions: `windows-latest` + `ubuntu-latest`): cargo fmt/clippy/test,
  typecheck, Vitest, Playwright smoke, license report.
- Docs skeleton (all files from the spec exist), LICENSE, NOTICE, dependency license report script.
- **Exit:** from a fresh clone in PowerShell, `npm install; npm run dev` shows the page with a
  number computed by WASM. Verified on this machine.

### M1 — Cards, evaluator, ranges, equity
- Card/combination types, 1326-combo indexing, suit isomorphism utilities.
- 7-card evaluator; **full 133,784,560-hand enumeration test** with the exact category counts;
  property tests against a slow reference evaluator.
- Range parser/printer (`22+, A2s+, KTs+, AJo+, 76s, T9s-54s`, weights `AKs:0.5`, combos
  `AhKh`), round-trip and property tests.
- Equity engine: exact enumeration and seeded Monte Carlo; hand/range vs hand/range; dead cards.
- 169×169 preflop equity table generated by `solver-cli` and committed with provenance.
  Checks: AA vs random ≈ 85.2%, mirrored matchups sum to 100%.
- Web: small equity calculator page (proves the WASM path for real work).

### M2 — CFR engine + validation harness
- Tabular CFR engine (DCFR α=1.5 β=0 γ=2, CFR+) over generic extensive-form games.
- Kuhn poker (value −1/18, exploitability → 0) and Leduc (monotone-in-the-limit decrease,
  below a stated threshold).
- Exact best-response / exploitability for tabular games.
- `solver-cli validate` writes `docs/VALIDATION.md` (generated, never hand-edited).

### M3 — River solver
- Postflop game-tree builder (bet/raise sizes as % pot per street and player, all-in
  threshold, max raises, rake with cap and no-flop-no-drop, stacks/pot).
- Range-vectorized DCFR/CFR+ traversal; O(n) showdown/fold evaluation with card-removal
  correction; exploitability in % pot and bb; determinism test.
- Validation: polarized-vs-bluff-catcher toy game at 33% / 75% / 150% pot (MDF P/(P+B),
  bluff share B/(P+2B)); independent brute-force best response; slow reference solver
  cross-check on random small river spots; suit-permutation and symmetry tests; goldens.
- Web: minimal river workbench (ranges, board, sizes, run, exploitability, strategy grid).

### M4 — Turn and flop
- Chance nodes with suit isomorphism; turn exact through river.
- Flop: full tree when the memory estimate fits, else an automatic, documented abstraction
  ladder with a visible warning naming what was reduced.
- Memory estimator before every solve; refuse cleanly above the budget, with suggestions.
- Worker protocol: progress, pause, cancel; UI never blocks.

### M5 — Preflop library
- Tier A (exact): heads-up push/fold Nash (chip EV and ICM), validated by exploitability ≈ 0
  and indifference of marginal hands. 3–6-handed push/fold solved by CFR with sampled
  multiway equities, labeled `solver_approx` with measured error.
- Tier B (approximate): 100 bb 6-max cash tree (RFI, vs open, vs 3-bet, vs 4-bet, squeeze,
  blind defense) solved with an equity-realization (EQR) model; stacks 20/40/60/100 bb, each
  actually generated (no silent interpolation). Sanity bands checked and reported.
- Provenance badges; chart explorer (13×13, split cells for mixes, EV, filters, compare view).

### M6 — Trainer core
- Preflop and postflop ("drill this spot") drills, EV-loss grading with mixed-strategy-aware
  categories, explanations generated from computed features (with non-contradiction tests),
  spaced repetition per spot family, stats with minimum samples and confidence intervals.

### M7 — Course, part 1
- Lesson platform (Markdown + front-matter + widgets + KaTeX + glossary hovers + quizzes).
- Levels 0–4 content, math drills, placement quiz, daily plan.

### M8 — Course, part 2
- Levels 5–7 content; range-building, board-texture and hand-reading drills;
  equity / ICM / variance widgets.

### M9 — Advanced
- Workbench polish (tree editor, node browser, runout explorer), node-locking and villain
  presets, aggregated flop reports (generated by CLI), hand-history import for post-session
  review, play mode (solved-strategy bots where available, labeled rule-based bots otherwise).

### M10 — Release
- PWA/offline, accessibility pass, performance pass, USER_GUIDE, release build, final
  KNOWN_LIMITS audit, "what to build next" summary.

## Risks and how they're handled

| Risk | Mitigation |
|---|---|
| Flop trees exceed browser memory | Estimator + automatic abstraction ladder + native CLI for big solves; warnings in UI |
| 100 bb preflop charts depend on an EQR model, not a full solve | Labeled `solver_approx`; model and parameters documented; sensitivity report; sanity bands |
| Multiplayer CFR (3+ players) has no equilibrium guarantee | Report measured per-player best-response gains; label approximate |
| Course content errors | Every numeric claim in a lesson is either computed live by a widget or generated by a script and tested |
| Scope is very large | Strict milestone order; each milestone is usable on its own |
| Windows / OneDrive path issues | Node-based scripts only, no symlinks, quoted paths, short root path, long-path note in README |
